# ThermoScan

**Satellite thermal intelligence · Stack Titans · SIH26162**

A working full-stack research prototype based on the supplied Smart India Hackathon slides. Real historical observations, real XGBoost inference, real data-source adapters, and **no synthetic production records**.

## Run it

Requirements: Linux (or Docker), Node.js 22, Python 3.11+, approximately 2 GB free disk space for dependencies and the training archive.

```bash
npm run setup
cp .env.example .env
npm run dev
```

Open the **ThermoScan dashboard on port 3000** in the Arena live preview. On your own machine, open the locally served frontend. `npm run dev` launches Next.js, Express and Python inference together. No API key is required to explore the real historical archive.

For a real MongoDB-backed deployment:

```bash
docker compose up --build
```

The frontend is published on port 3000; MongoDB, Express and the ML service remain on the private Compose network. Set `ADMIN_API_KEY` before public exposure. Do not publish MongoDB or internal ML ports publicly.

### Dashboard workflows

- Historical / near-real-time modes are deliberately separate.
- Region bounding boxes, time windows, source-type filters, actual activity charts and source-type distributions.
- Interactive canvas map, real coordinate tooltips, selectable points, layer controls, fullscreen view and map reset.
- Full paginated catalog, search and sorting; counters/exports include all matching records, not only mapped points.
- Observation detail with measured FRP/brightness, true model scores, past-only recurrence and on-demand evidence retrieval.
- Analyst watchlist and review notes, persisted across refreshes; source snapshots remain available after a live feed rolls forward.
- CSV/GeoJSON exports with source/mode/model provenance.
- Historical CSV import with validation; background training with actual pipeline stages.
- Model card, real holdout metrics, feature importance, confusion matrices and per-class limitations.
- Explicit API health and credential/configuration status.

## What is actually verified here

**Working:** the full historical flow, actual model training/inference, real-file imports, filtering, exports, model reporting and local review persistence.

**Not claimed as verified:** successful live NASA/OSM/Sentinel retrieval in this sandbox. Direct HTTPS connections to those upstream hosts failed during implementation. The adapters fail visibly, and no fake data is substituted. MongoDB was not available here; Docker Compose provisions a real instance for a network-enabled deployment. Optional population exposure is not configured.

The active model is a **thermal + temporal baseline**. Sentinel/OSM context retrieval and a fused-training path are implemented, but no successful fused-model run is claimed without measured contextual data.

## Real historical data and trained model

The reproducible baseline uses an explicitly attributed, commit-pinned public mirror of a NASA-format India VIIRS archive:

- **January–March 2025**, 316,036 input rows, one duplicate removed.
- Source: [firms_historical_india.csv](https://github.com/UjjwalKumar7209/sih-2026/blob/30ae6eb05c400b1d40aac7daa4c4a9bbceec667f/SIH_Industrial_Fire_AI/firms_historical_india.csv).
- Source SHA-256: `62b397c086bf1934010fd86987506e8aca45d74a9fc0270cd434128a9a9a3db6`.
- **67,359 real source rows** from the final seven calendar days are included as a compact historical map window, with causal history features derived from the full quarter.
- Original source rows and labels are not generated by this app. The mirror's equivalence to a freshly reprocessed official archive has not been independently verified; this is clearly disclosed.

```bash
npm run data:download    # Explicit, pinned historical mirror with checksum check
npm run model:train      # Actual XGBoost fit and date/location holdouts
```

For official data, other years and genuine Sentinel/OSM enrichment, read **[the complete historical-data guide](docs/HISTORICAL_DATA.md)**. It is also available inside the dashboard at `/guide`.

### Honest evaluation

The bundled model trained on **83,356 observations**, with **44,237** observations in the strict unseen-date + unseen-spatial-block test set. Macro-F1 is **0.6274**, and static-source F1 is **0.8862**. Overall accuracy is 0.9923, but the majority-class baseline is already 0.9691; presenting accuracy alone would be misleading.

The rare offshore class has inadequate held-out performance. Serving abstains for poorly validated classes and low maximum model scores. This conservative display policy uses holdout diagnostics; the reported metrics belong to the ungated classifier, not an independently validated abstention policy. The model predicts NASA **inferred source types**, not independently confirmed industrial incidents, and does not distinguish forest fire from crop-residue burning.

Important NASA label caveat: Collection-2 monthly type labels were affected by a bug corrected in May 2025. The mirror's reprocessing revision is unverified. Get freshly reprocessed standard archives and independent incident labels before scientific/operational deployment.

## Configuration

Copy `.env.example`. Keep secrets in `.env`, which is ignored by Git.

- `FIRMS_MAP_KEY`: optional free NASA key for area/date API access; public regional CSVs work without it if reachable.
- `MONGODB_URI`: real MongoDB URI. No credentials are logged or sent to the client.
- `ADMIN_API_KEY`: protects imports, training, source checks and review mutations; the UI can hold it in browser memory only. The Python service also requires internal authorization when this is set.
- `INTERNAL_SERVICE_KEY`: optional separate backend-to-ML key. Keep it server-side.
- `DEFAULT_DATA_MODE`: `archive` (default) or `live`.
- `POLL_INTERVAL_MINUTES`: 15 by default (minimum 5). NASA regional CSVs are published about hourly; faster UI polling does not create observations.
- `WORLDPOP_RASTER_URL`, `WORLDPOP_YEAR`: optional genuine population-count raster and reference year. No configuration means unknown exposure.

All browser API requests are relative `/api/...`. Next.js proxies to Express, and Express calls Python. Development binds to `0.0.0.0` and permits Arena preview hosts.

## Tests and checks

```bash
npm run typecheck
npm test
npm run test:ml
npm run build
# With the application running:
npm run test:e2e
# Also exercise a real full-archive background retrain (optional):
npm run test:e2e -- --train
```

Tests cover real CSV parsing, bad inputs, UTC handling, deduplication, target/future leakage, actual artifact inference, row/provenance checks, historical/live separation, API filters, exports and browser workflows. Unit-level fault injection is confined to tests; it never supplies data to the application.

The E2E setup can use Playwright's regular Chromium, a system browser via `CHROMIUM_EXECUTABLE_PATH`, or the installed `@sparticuz/chromium` binary (useful when browser-CDN access is blocked). Browser binaries and screenshots are ignored, not committed.

Validation results are recorded in [docs/VALIDATION.md](docs/VALIDATION.md). See also the [architecture](docs/ARCHITECTURE.md) and [source attribution](docs/SOURCES.md).

For a local production frontend with the API and Python service already running:

```bash
npm run build
npm start
```

`npm start` serves the actual standalone build and copies its required static assets. Rebuild after changing `INTERNAL_API_URL`, because Next.js rewrites are compiled into the build.

## Boundaries before deployment

This is decision support, **not an emergency dispatch system**. No SMS/email is sent. FRP ≥ 50 MW is a transparent review threshold, not a validated public-safety risk model. A near-industrial hotspot is not a confirmed industrial fire. Optical scenes, map snapshots and modeled population have different times, resolutions and coverage. Add real authentication, incident-level ground truth, calibrated external validation, background workers, database backups and operational monitoring before deploying for public safety.
